## 1. 愿景与目标

**愿景**：打造一套覆盖「销售—装维—运营」全链路的宽带业务平台，以可安装性校验、智能派单、装维 SLA 赔付、套餐灵活升级与流量透明化为核心竞争力，对标中国电信「美好家/慢必赔」与中国移动「和家庭/超时赔」的最佳实践。

**核心目标（SMART 化）**
- 前端办理转化率：覆盖查询→下单链路可装性实时校验，避免超卖。
- 装维时效：相邻小区合并派单 + 时段容量管控，超容自动拦截。
- 服务可信：SLA 规则引擎驱动「慢必赔/不达标赔」自动赔付。
- 经营灵活：套餐升档/加购在线办理，补差计算透明可追溯。
- 运营可控：PC 后台全模块可用，权限最小化（21 个权限码 + 菜单驱动）。

---

## 2. 规划原则

1. **算法与框架解耦**：核心算法保持纯 Java 可独立验证，降低回归风险。
2. **接口先行、契约稳定**：REST 接口契约先定义（已稳定 **62 个**），前后端并行开发。
3. **垂直切片交付**：按业务域（community / install / product / system）逐模块打通「接口 → 前端 → DB」。
4. **基础设施按需后置**：DB / 安全按阶段接入，避免 over-engineering；**明确不引入的能力就不做半成品**
   （如不引入 Spring Cloud、不引入 Apollo）。

## 3. 阶段路线图

> 周期以「相对工期」标注，实际排期结合资源确认。**Phase 1–3 已完成**。

### ✅ Phase 1 · 核心底座与接口契约（已完成）
- **范围**：后端核心算法 + 接口契约；客户端骨架打通关键链路。
- **交付**：设计稿 v1.9、后端模块化实现 + 6 个可运行 Demo、客户端小程序骨架（后于 Phase 4 扩至 20 页 + 师傅端 8 页）。
- **达成**：全部接口可 curl 返回结构化 JSON；小程序关键页可本地预览。

### ✅ Phase 2 · 数据持久化与真实联调（已完成）
- **范围**：引入 MySQL 驱动，建表并去除 mock。
- **实际交付**：MySQL 8.4 接入；**25 张表** + 幂等 `schema.sql` / `data.sql`（启动自动初始化，不覆盖运行期数据）；
  流量/套餐升级改真实聚合与落库；小程序与后端 2 处字段契约不一致修复。
- **达成**：端到端链路 **小程序 → 后端 → MySQL** 实测打通。

### ✅ Phase 3 · PC 后台与权限体系（已完成）
- **范围**：搭建 web-admin（Vue 3 + Element Plus + Pinia + Vue Router + Vite），落地设计稿 16 个后台模块，接入 RBAC。
- **实际交付**：
  - `web-admin` 工程：**25 个 .vue 页面 / 22 条路由**，全量对接真实接口，主题靛 `#4f46e5`；
    侧边栏由后端菜单树驱动，路由守卫 + `v-perm` 双重控制，接口不可达时演示兜底。
  - 后端第 4 模块 `system`：`sys_*` 六表 + Spring Security 6 无状态 JWT + 21 个权限码 + 操作审计；
    后台聚合接口（看板 / 订单 / 监控 / 报表）一并补齐。
  - 接口由 13 → **62 个**，表由 17 → **25 张**。
- **达成**：实测鉴权矩阵 —— 无 token → 401、越权 → 403、授权内 → 200；
  各角色菜单数分别为 26 / 19 / 4 / 4；`JwtUtilTest` 7 条回归用例通过。

### ✅ Phase 4 · 小程序补页与登录态（已完成）
- **目标**：三端齐备，C 端可完整走完「查覆盖 → 下单 → 升档 → 报修 → 评价」。
- **范围**：
  - 客户端由 7 页扩至 **20 页**：新装/移机/续费/提速/报修/智慧家庭/自助服务/评价投诉、订单列表与详情、地址管理、个人中心、设置、登录全部落页。
  - 新建师傅端独立工程 `broadband-worker`（橙 `#ea580c`）**8 页**：工单/详情/完工确认/容量/路线/评价/个人中心/登录。
  - 登录态骨架：两端 `request()` 注入 `Bearer` token、`auth.js` 提供 `isLogin/requireLogin`、`profile` 页 `onShow` 登录门禁、真实登录（演示码 1234，调 miniapp-login 换 JWT）。
- **退出标准（已达成）**：客户端全页面可操作（c 端开放层）；师傅端可查看工单与完工确认入口；登录态骨架就位，待接后端鉴权。

### 🔜 Phase 5 · 交付与运维增强（建议 3~4 周）
- **目标**：可部署、可观测、可运营。
- **范围**：
  - 部署：Nginx 托管 `web-admin/dist` + 反代 `/api` 到 `:8082`，systemd / 容器化二选一。
  - 可观测：在现有轻量指标（JVM / 内存 / 接口往返 / DB 连通）之上接入 Prometheus + 日志中心。
  - 业务增强：工单状态机流转与改派、SLA 规则在线编辑、套餐上下架审批流。
  - 参数治理：派单容量与 SLA 规则以库内参数为准（已具备在线编辑基础），叠加环境变量覆盖。
- **退出标准**：一键部署脚本可用；核心指标看板可用。

## 4. 技术演进路线

| 能力 | 现状（v1.1） | 目标 |
|---|---|---|

## 5. 风险与对策

| 风险 | 影响 | 对策 | 状态 |
|---|---|---|---|
| 设计稿规划页多、实现面广 | 进度压力 | 垂直切片，先打通核心链路再扩展 | 持续 |
| mock 与真实数据差异 | 联调返工 | 接口契约先行；已在 Phase 2 暴露并修复 2 处字段契约不一致 | 已缓解 |
| 师傅端小程序未启动 | 交付不完整 | Phase 4 集中资源建页；后端 `worker_capacity` 与容量接口已就绪，无阻塞 | ✅ 已落地（8 页） |
| 容量 / SLA 规则需运营确认 | 业务正确性 | 规则参数化入库，先默认值后调优；不做外部配置中心以降低运维面 | 持续 |
| 多端主题与权限一致性 | 体验 / 安全 | 统一设计 token（蓝/橙/靛）与 RBAC 模型；菜单树由后端单一来源下发 | 已落地 |
| 自研 JWT 的正确性 | 安全 | 零三方依赖换取可审计性，但必须配回归单测（已补 7 条）；catch 必须留日志 | 已落地 |
| 生产默认密钥/口令 | 安全 | `app.jwt.secret` 环境变量覆盖；首登强制改密；README/运维手册明示 | 待办（上线前） |

## 6. 验收标准

- **功能**：62 个接口 100% 可用且读写真实数据；PC 后台 22 个业务页可管理；客户端 20 页 + 师傅端 8 页全部可操作（c 端开放层，登录态骨架就位）。
- **质量**：核心算法有 Demo 覆盖；JWT 有 7 条回归单测；关键路径有 curl 联调用例（鉴权矩阵已实测）。
- **安全**：RBAC 生效 —— 未认证 401、越权 403、授权内 200；登录失败 / 越权 / 写操作均落审计日志。
- **运维**：提供建表 SQL、部署方式、配置模板、故障排查手册（见《运维操作说明书》）。
- **可观测**：关键业务指标有看板（SLA 达标率、派单容量、流量阈值、接口往返与错误率）。
