# 宽带业务管理系统 · 后续迭代优化版本规划

> 版本基线：v1.9（commit `5224b45`「三端设计系统落地 + UI 组件与文档/原型交付」）
> 规划日期：2026-09-16
> 目标：在已完成的「下单→支付→派单→装机→SLA 赔付→评价」业务闭环之上，补齐数据闭环、交易真闭环与工程化能力。

---

## 一、当前已完成能力（基线）

- **三端工程**：微信小程序（客户端 20 页 / 师傅端 8 页）+ Vue3 PC 后台（33 个 .vue 页面）+ Spring Boot 3.2 后端（62 接口 / 25 表）。
- **核心业务闭环**：套餐订购、模拟支付、智能派单（相邻小区 3-4 单/时段）、装机 SLA（时限类+速率类双评估）、赔付、评价全链路联调 36 项断言全绿。
- **RBAC**：自研 HS256 JWT、21 权限码 / 5 角色 / 26 菜单三处同源。
- **运营聚合**：数据看板、流量总览、订单/工单、性能监控（JVM/DB/接口调用/慢接口）后端均已落地。
- **统一设计系统**：三端设计令牌 + 通用组件（EmptyState / StatusTag / StatCard / ChartBox / SourceTag）已收敛。

## 三、版本路线图

### v1.10 · 数据分析闭环（本轮）
- [x] `GET /api/admin/sales/report`：按 `sales_name` 聚合 biz_order（订单量/业绩/完成率）。
- [x] `GET /api/admin/finance/report`：近 6 月营收/退款/SLA 赔付/应收（biz_order + compensation）。
- [x] 前端销售/财务两页从「演示数据」自动切「实时数据」。
- [x] 数据模型补强：`biz_order` 增加 `region`（片区）字段，消除销售页「负责片区」空值。
- 验收：页面 SourceTag 显示「实时数据」，数据与 `biz_order` 表一致。

### v1.11 · 交易真闭环（本轮已落地 ✅，微信支付真集成除外）
- [ ] 微信支付真集成：`MockWeChatPayServiceImpl` → 真实 APIv3（需 G4 凭证，阻塞）。
- [x] 退款 / 对账状态机：`biz_order` 增加 `REFUND` 状态（`order_refund` 表 + 状态机），财务退款口径对齐（`finance/report` 退款=REFUND、取消=CANCELLED，营销汇总排除 REFUND）。新增 10 个接口（C 端退款申请 / 后台退款审批驳回 / 发票申请开票驳回 / 评价回填）。
- [x] 电子发票占位（开票申请 + 状态）：`invoice_apply` 表 + C 端申请/查询 + 后台开票/驳回。
- [x] 师傅端完工后自动生成「服务评价」推送（评价闭环增强）：`WorkerController.complete()` 自动插入 `review(status=TO_EVALUATE)`，客户经 `/api/review/submit/{id}` 回填闭环。

### v1.12 · 质量与运维工程化（本轮已落地 ✅）
- [x] CI/CD：GitHub Actions 构建 + 单元测试 + 容器镜像（`.github/workflows/ci.yml` + `backend/Dockerfile` 多阶段）。
- [x] 压测：k6 脚本覆盖登录→订单→销售→工单→派单容量，给出容量基线（`scripts/k6-load-test.js`）。
- [x] 监控深化（G6）：`/actuator/prometheus` 暴露 HTTP/JVM/GC/线程指标（actuator 自动埋点），告警规则随监控页阈值生效（`scripts/prometheus/`）。
- [x] 配置治理（G7）：多环境 profile（dev/prod）+ 配置变更审计约定，仍坚持 Spring Boot 原生配置。

### v2.0 · 体验与能力扩展

## 四、优先级建议

1. **P0（本轮）**：G1 / G2 销售与财务后端——纯读侧聚合，零外部依赖，收益最高。
2. **P1（下轮）**：G4 微信支付真集成（需用户提供凭证）、G10 后台扩展。
3. **P2（工程化）**：G8 / G9 CI/CD 与压测、G6 监控深化。
4. **P3（体验）**：G5 师傅端验收、G11 国际化。

---

## 五、模块约束（不变）

- 后端业务模块上限 **5 个**（当前 4：community / install / product / system）。新增聚合类接口归入 `system` 的「平台聚合」（`AdminPlatformController`），保持 4 模块单向可拆。
- 配置坚持 Spring Boot 原生（yml + 环境变量），不引入 Apollo。
