## 1. 系统组成与端口规划

系统采用**单体**架构（非微服务），不引入注册中心 / 配置中心（Apollo）。后端为单个 Spring Boot 应用，前端与小程序通过 Nginx 反向代理同源访问后端 8082 端口。配置坚持 Spring Boot 原生（`yml` + 环境变量）。

| 组件 | 技术 | 默认端口 | 说明 |
|------|------|----------|------|
| 后端服务（broadband-backend） | Spring Boot 3.2.1 / JDK 21 | **8082** | 单体应用，全部业务 API |
| MySQL | 8.4.x | **3306** | 库名 `broadband`，账号 `broadband` |
| PC 管理后台（web-admin） | Vue 3.5 + Vite 5 | 构建后由 **Nginx 80/443** 托管；开发态 5173 | 纯静态资源 |
| 微信小程序（客户端 / 师傅端） | 微信原生 | — | 通过 HTTPS 访问后端 8082 |

## 3. 数据库初始化

后端启动参数带 `createDatabaseIfNotExist=true`，首次启动自动建库；表结构与种子数据由 `db/schema.sql` + `db/data.sql` 启动自动执行（幂等）。也可手工建库授权：

```sql
CREATE DATABASE IF NOT EXISTS broadband DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'broadband'@'%' IDENTIFIED BY '<你的密码>';
GRANT ALL PRIVILEGES ON broadband.* TO 'broadband'@'%';
FLUSH PRIVILEGES;
```

> **表结构无需手工创建**：应用启动时会执行 `db/schema.sql`（`CREATE TABLE IF NOT EXISTS`）与 `db/data.sql`（`INSERT IGNORE`），幂等且不会覆盖运行期新增数据。

手动初始化（如需独立执行）：

```bash
mysql -u<user> -p < broadband < backend/src/main/resources/db/schema.sql
mysql -u<user> -p < broadband < backend/src/main/resources/db/data.sql
```

## 4. 后端构建与启动

### 4.1 构建

```bash
cd backend
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
MVN=~/Documents/localRepository/devRepository/maven/bin/mvn
$MVN clean package            # 执行 JwtUtilTest（7 条）；仅打包可加 -DskipTests
# 产物：target/broadband-backend-1.0.0.jar
```

离线构建：`/Users/mezo/Documents/localRepository/devRepository/maven/bin/mvn -o -q package -DskipTests`

### 4.2 启动（生产姿态，单 JVM）

> ⚠️ **禁止** `mvn spring-boot:run` 用于生产验证：本沙箱中该方式会被注入随机端口（fork JVM）。必须用 `java -jar` 显式指定端口。

```bash
export DB_HOST=127.0.0.1
export DB_PORT=3306
export DB_NAME=broadband
export DB_USERNAME=broadband
export DB_PASSWORD=broadband

java -jar target/broadband-backend-1.0.0.jar --server.port=8082
```

> ⚠️ **端口优先级坑**：命令行 `--server.port` > 环境变量 > `application.yml`。若宿主机/沙箱注入了 `SERVER_PORT` 之类的变量导致端口不是你期望的，请显式加 `--server.port=8082`。

多环境 Profile：`java -jar broadband-backend-1.0.0.jar --spring.profiles.active=prod --server.port=8082`
环境变量注入优先级：`命令行参数 > 环境变量 > application-prod.yml > application.yml`。

### 4.3 冒烟验证

```bash
B=http://127.0.0.1:8082

# 1) 未带 token → 期望 401
curl -s -o /dev/null -w "%{http_code}\n" "$B/api/sla/rules"

# 2) 登录取 token
TOK=$(curl -s -X POST "$B/api/auth/login" -H 'Content-Type: application/json' \
      -d '{"username":"admin","password":"admin123"}' \
      | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# 3) 带 token 取菜单树与权限码
curl -s -H "Authorization: Bearer $TOK" "$B/api/auth/me" | head -c 400

# 4) 越权（财务账号访问 SLA）→ 期望 403
FT=$(curl -s -X POST "$B/api/auth/login" -H 'Content-Type: application/json' \
     -d '{"username":"zhaomin","password":"zhaomin123"}' \
     | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $FT" "$B/api/sla/rules"
```

## 5. 前端（web-admin）构建与 Nginx 托管

```bash
cd web-admin
npm install --registry=https://registry.npmmirror.com
npm run build            # 产出 dist/
```

开发态：`npm run dev`（http://127.0.0.1:5173，`VITE_API_TARGET` 指向后端）。

Nginx 反代示例（含 SPA history 回落与完整头）：

```nginx
server {
    listen 80;
    server_name bb.example.com;
    root /opt/broadband/web-admin/dist;
    index index.html;

    location / { try_files $uri $uri/ /index.html; }

    location /api/ {
        proxy_pass http://127.0.0.1:8082;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

> 登录页使用 `admin / admin123`。若后端不可达且 `VITE_ALLOW_DEMO_LOGIN=true`，会降级为本地演示登录（页头标注演示态）。后端进程建议 systemd 托管（`ExecStart` 用绝对路径 `java -jar`，`Environment=` 注入 `DB_*` 与 `JWT_SECRET`），或容器化。

### 5.1 容器化部署

```bash
docker build -t broadband-backend:1.0.1 backend/
docker run -d -p 8082:8082 \
  -e DB_HOST=$DB_HOST -e DB_USERNAME=broadband -e DB_PASSWORD=broadband \
  broadband-backend:1.0.1
```

## 6. 小程序部署与联调

**客户端 `broadband-miniapp/`（蓝 #2563eb，15 页）**
1. 用微信开发者工具打开 `broadband-miniapp/`。
2. 在 `app.js` 的 `globalData.baseUrl` 填入后端地址（本地：`http://<本机IP>:8082`）。
3. `utils/api.js` 的 `request()` 统一注入 `Bearer` token，且**非 2xx 显式 reject**（报错会被页面捕获并提示，不再静默无数据）。
4. 登录态（真实后端鉴权）：`pages/login` 调 `POST /api/auth/miniapp-login`（演示码 `1234` → 真实 JWT）。

**师傅端 `broadband-worker/`（橙 #ea580c，8 页，独立工程）**
1. 用微信开发者工具**另开一个工程**打开 `broadband-worker/`（与客户端是两个独立小程序，且 `project.config.json` 的 `appid` 须为**师傅端独立 AppID**，切勿与客户端共用）。
2. 提审前将 `appid` 占位 `wxWORKER_APPID_TODO` 替换为在微信公众平台新注册的师傅端小程序 AppID，并通过 `WECHAT_WORKER_APPID` / `WECHAT_WORKER_SECRET` 注入后端。

## 7. 配置说明（yml / 环境变量 / DB_USERNAME 覆盖）

`backend/src/main/resources/application.yml`（摘录）：

```yaml
server:
  port: 8082
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${DB_HOST:127.0.0.1}:${DB_PORT:3306}/${DB_NAME:broadband}?createDatabaseIfNotExist=true&useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD:}
  sql:
    init:
      mode: always
      schema-locations: classpath:db/schema.sql
      data-locations: classpath:db/data.sql
app:
  jwt:
    secret: ${JWT_SECRET:broadband-rbac-secret-please-change-in-production}   # ⚠️ 生产必须覆盖
    ttl-minutes: 120
  security:
    protect-client-api: false               # true = 小程序 c 端接口也强制鉴权
  wechat:
    worker:
      appid: ${WECHAT_WORKER_APPID:}
      secret: ${WECHAT_WORKER_SECRET:}
```

> 数据源用户名通过 `DB_USERNAME` 环境变量覆盖（默认值 `root`）。生产务必用环境变量注入 `DB_USERNAME` / `DB_PASSWORD` / `JWT_SECRET`，**不要写进代码仓库**。

**环境变量清单**

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `127.0.0.1` / `3306` / `broadband` | 数据源 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / 空 | **不要写进代码仓库**；`DB_USERNAME` 覆盖 yml 默认 |
| `JWT_SECRET` | 开发用默认串 | 生产必须替换为高强度随机串 |
| `WECHAT_APPID` | `wxcc344ad7f4f849d4` | 客户端小程序 AppID（已回填真实值） |
| `WECHAT_SECRET` | 空 | 客户端小程序 AppSecret，生产用环境变量注入 |
| `WECHAT_WORKER_APPID` / `WECHAT_WORKER_SECRET` | 空 | 师傅端小程序（broadband-worker）独立 AppID/Secret |
| `SERVER_PORT` | — | 注意与命令行 `--server.port` 的优先级关系 |

**微信小程序登录（code2Session）与演示态切换**
- 未注入 `WECHAT_SECRET` → 自动回退**演示分支**：手机号 + 固定验证码 `1234`，签发演示 JWT（`wechatBound=false`）。
- 注入 `WECHAT_SECRET` → 自动切换**真实路径**：用 `wx.login()` 换取 `code` 调微信 `jscode2session` 换取 `openid`，签发真实 JWT（`wechatBound=true`）。前端无需改动。

```bash
# 方式一：先打包再以环境变量运行 jar
mvn -q clean package -DskipTests
WECHAT_APPID=wxcc344ad7f4f849d4 WECHAT_SECRET=你的真实AppSecret \
  java -jar target/broadband-backend-1.0.0.jar
```

> 师傅端走独立的 `POST /api/auth/worker-login`，按手机号鉴权、不依赖微信 openid，不受 `WECHAT_SECRET` 影响（生产应替换为真实短信网关校验）。

## 8. 账号与权限

初始密码由 `RbacInitializer` 在首次启动时以 **BCrypt** 写入（幂等：已有密码不覆盖）。

| 账号 | 初始密码 | 角色 | 可见菜单 | 权限码 |
|---|---|---|---|---|
| admin | admin123 | ADMIN 超级管理员 | 26 | 21 |
| liuwei | liuwei123 | OPERATOR 运营专员 | 19 | 15 |
| zhaomin | zhaomin123 | FINANCE 财务 | 4 | 4 |
| wangfang | wangfang123 | CS 客服 | 4 | 4 |

> ⚠️ **上线前必做**：① 修改全部默认密码；② 通过 `JWT_SECRET` 覆盖默认密钥；③ 删除或禁用不需要的演示账号。

权限模型：
- 权限码来源唯一：`sys_menu.perm`。三处同源 —— **DB 菜单表 / 后端 `@PreAuthorize("hasAuthority('xxx')")` / 前端路由 `meta.perm`**。
- 角色与权限码**每请求实时查库**（不固化进 token），后台调整授权后**立即生效，无需重新登录**。
- 登录失败、越权访问、写操作均记入 `sys_oper_log`，后台 `/system/log` 可查。

## 9. 监控与告警

### 9.1 应用指标（Actuator + Prometheus）

| 端点 | 用途 |
|------|------|
| `/actuator/health` | 健康检查（K8s/Docker 探针） |
| `/actuator/prometheus` | Prometheus 拉取（HTTP/JVM/GC/线程 自动埋点） |

安全：端点已在 `SecurityConfig` 放行（`/actuator/**` 只读）。

### 9.2 告警规则

`scripts/prometheus/prometheus.yml` + `alert.rules.yml`：平均时延 > 1s 告警；5xx 错误率 > 5% 告警；JVM 堆使用 > 85% 告警。

### 9.3 内置轻量指标与日志

- `ApiMetricsFilter` 采集接口往返与错误率，聚合在 `GET /api/admin/monitor/overview`（含 JVM 内存、健康状态、DB 连通），PC 后台 `/monitor` 页直接消费。
- 审计日志：`sys_oper_log`，后台 `/system/log` 可查。
- 应用日志：默认控制台输出；关键路径打日志（派单结果/超容、SLA 评估与赔付、JWT 鉴权失败原因）。
- 临时调整日志级别：`java -jar target/broadband-backend-1.0.0.jar --logging.level.com.broadband.system.security=DEBUG`

### 9.4 压测基线

`scripts/k6-load-test.js`：覆盖 登录→订单→销售→工单→派单，20→50 VU 基线，P95 < 800ms、失败率 < 1%。

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动报 `Invalid value type for attribute 'factoryBeanObjectType'` | 用了 `mybatis-plus-boot-starter`（带 `mybatis-spring:2.x`），与 Spring 6.1 不兼容 | 改用 `mybatis-plus-spring-boot3-starter` |
| 登录成功、token 正确，但所有受保护接口一律 401 | ① JWT 解析异常被过滤器静默吞掉；② 密钥不一致 | 打开 `--logging.level.com.broadband.system.security=DEBUG` 看 `JWT 鉴权失败 uri=... 原因=...` |
| 返回 `DataIntegrityViolationException` | 联表 `SELECT id` 未加表别名 → 列歧义 | 给联表查询的列**全部加表别名**（如 `o.id`） |
| 启动后端口不是 8082 | 宿主机/沙箱注入了 `SERVER_PORT` | 命令行显式 `--server.port=8082` |
| 服务启动即退出 | `spring.sql.init` 脚本失败或数据源连不上 | 看启动日志中 `schema.sql` / `data.sql` 附近异常；校验 `DB_*` |
| `command not found: mvn` | Maven 未加入 PATH | 用绝对路径 `~/Documents/localRepository/devRepository/maven/bin/mvn` |
| 前端 `npm install` 极慢 | 默认走 `registry.npmjs.org` | `npm config set registry https://registry.npmmirror.com` |
| 前端显示「演示数据」 | 接口不可达触发兜底 | 确认后端已启动且 `/api` 代理指向正确端口 |
| 小程序请求失败 | `baseUrl` 未配置 | 配 `globalData.baseUrl`；本地联调用 `http://<本机IP>:8082` |
| 派单全超容 | 单师傅时段容量上限过低 | 调整 `worker_capacity`（相邻 3–4 / 非相邻 1–2） |
| 越权却返回 401 | 说明认证就没通过（token 无效/过期） | 先按 401 排查；401=未认证，403=已认证但无权限 |
| 全部接口 401（`iat/exp` 解析异常） | JWT 声明数字解析缺陷（已修复） | 升级到含修复的版本 |

## 12. 数据备份与恢复

| 对象 | 频率 | 方式 |
|------|------|------|
| MySQL | 每日全量 + 增量 binlog | `mysqldump` / 云 RDS 自动备份 |
| 应用 jar | 随发版归档 | 制品库（镜像 tag） |
| 静态资源 | 随发版 | 对象存储 / CDN |

RTO < 30min，RPO < 5min（binlog）。

```bash
# 逻辑全量备份（每日）
mysqldump -ubroadband -p --single-transaction --routines --events \
  broadband > /backup/broadband_$(date +%F).sql

# 恢复
mysql -ubroadband -p broadband < /backup/broadband_YYYY-MM-DD.sql
```

**常用运维 SQL**

```sql
-- 表与行数概览
SELECT table_name, table_rows FROM information_schema.tables
 WHERE table_schema='broadband' ORDER BY table_name;

-- 重复演示派单前，把工单重置为待派
UPDATE work_order SET status='PENDING', worker_id=NULL, cluster_id=NULL, adjacent_route=NULL;

-- 查看最近的越权与登录失败记录
SELECT created_time, username, action, result, ip FROM sys_oper_log
 WHERE result LIKE '失败%' OR action LIKE '%未携带%' ORDER BY id DESC LIMIT 20;
```

> 说明：数据库 schema 向后兼容（仅追加列，不删改），回滚 jar 时无需回退数据。应用 jar 保留最近 3 个版本用于回滚。
