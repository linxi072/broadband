## 2. 迭代阶段划分（目标范围 / 交付内容 / 实现要点 / 依赖 / 排序）

### 阶段 0 · 收口前置（0.5~1 周，P0，无外部依赖）
- **目标范围**：消除「审阅级交付」风险，让所有已写代码可编译、可版本化、可安全治理，为后续一切打底。
- **交付内容**：
  1. B0 后端本机 `mvn -o compile` 验证（修复任何编译报错，重点核对 v1.15 新增 `PaymentService`/`IntelligenceController`/菜单种子列名与包扫描）。
  2. B1 `git commit` + `git push`（建议新开 `release/v1.15` 或沿用 `V1.0.2` 分支）。
  3. T-02 安全治理：`JWT_SECRET` 走环境变量覆盖；admin 首登强制改密；输出安全检查清单。
  4. B2 文档一致性收口（总览 §6.4 旧注释作废，与迭代计划 §4.4 对齐）。
- **实现要点**：编译验证脚本化；安全配置零硬编码；清单逐项勾选。
- **依赖**：无（push 需用户本机/连接器或 GitHub Token）。
- **入口/出口**：入口=当前代码；出口=`compile` 绿 + 已 push + 安全清单勾选 + 文档一致。
- **排序位置**：**最前，所有后续阶段的前置闸门。**

### 阶段 1 · 工程化与验收（v1.16，1~2 周，P0/P2）
- **目标范围**：长稳可用、师傅端可提审、配置可热更——把"能跑"升级为"可运维"。
- **交付内容**：T-06 压测长稳脚本；T-01 师傅端验收（AppID 注册注入 `project.config.json`、视觉验收、提审包）；T-05 配置热刷新。
- **实现要点**：JMeter/自研长稳脚本采集错误率与 GC；`sys_config` 变更监听 + `/actuator/refresh` 或 `@RefreshScope`；worker `wxcc344ad7f4f849d4` 同款注册流程。
- **依赖**：阶段 0（编译/push 完成）。
- **排序位置**：阶段 0 之后立即进行；与阶段 2 可部分并行（工程化不阻塞业务）。

### 阶段 2 · 后台深化与真实支付闭环（v1.17，2~3 周，P1，关键路径）
- **目标范围**：看板从"能看"到"实时 + 可下钻 + 真实交易"，关闭最大商业阻塞。
- **交付内容**：T-04 三页深化；US-2.2 报表下钻接口核对/补齐；T-03 真实微信支付集成（凭证到位时排首）。
- **实现要点**：聚合接口复用 intelligence 已沉淀的 `customer/biz_order/points_account/review` 口径；`WeChatPayServiceImpl` 凭证切换零代码改动；退款/对账单对接 `pay_transaction` 状态机。
- **依赖**：阶段 0（必）；T-03 额外依赖**真实微信凭证**（未到位则保留 Mock 并标注，机制已就绪）。
- **排序位置**：业务价值最高，阶段 1 并行或紧随；T-03 在凭证到位瞬间插队到本阶段首。

### 阶段 3 · 客户端运营留存联调与埋点（v1.18，1~2 周，P1/P2）
- **目标范围**：C 端运营留存闭环联调 + 为智能推荐积累行为数据。
- **交付内容**：小程序 v1.14 四页真实接口联调；`order/confirm` 真闭环真机验证；行为埋点（`recommend/shortcuts` 前置）。
- **实现要点**：小程序真实 JWT 联调（CUSTOMER 令牌）；埋点接口/表设计（事件/时间戳/用户维度）。
- **依赖**：阶段 1（后端接口稳定）+ 阶段 2（支付真闭环）。
- **排序位置**：在后端接口稳定后，作为"端到端可用性"收口。

### 阶段 4 · V2.0 智能化与多端（3~4 周，P2/P3）
- **目标范围**：体验与能力扩展——多住宅统一管、首页智能推荐、宽带暂停/恢复、中英双语。
- **交付内容**：US-3.1 多住宅切换；US-3.2 智能推荐（依赖阶段 3 埋点积累）；US-3.3 宽带暂停/恢复；US-3.4 i18n。
- **实现要点**：`household_id` 维度隔离（查询/写入全链路）；`recommend/shortcuts` 行为聚合；`broadband` pause/resume 状态机与计费口径；i18n 资源抽取（脚手架 + 至少 1 个核心页可切换）。
- **依赖**：阶段 3（埋点）；T-07 框架（i18n）；US-3.1 可与阶段 1/2 并行启动。
- **排序位置**：体验层，置于核心闭环稳固之后；可与 M15 部分并行（若补员）。

### 阶段 5 · M15 上线保障（1~2 周，硬性门禁）
- **目标范围**：生产可交付——流水线 + 部署 + 安全门禁 + 文档复盘。
- **交付内容**：M15-CI（GitHub Actions 构建+单测+镜像）；M15-DEP（生产 Nginx 反代 :8082）；M15-DOC（文档终版 + 复盘）。
- **实现要点**：流水线脚本化；**T-02 安全治理为硬性门禁——未完成不得上线**。
- **依赖**：阶段 1~4；T-02（阶段 0 已启动，此处闭环）。
- **排序位置**：**最后闸门**，所有业务迭代完成后触发。

## 3. 先后顺序与关键路径

```
阶段0(收口前置) ──► 阶段1(工程化/验收) ──┐
   │                  │  └─ T-05/T-06 持续   │
   │                  ▼                       ▼
   │            阶段2(后台深化+真实支付) ──► 阶段3(C端联调+埋点) ──► 阶段4(V2.0 智能化)
   │                  ▲ T-03 凭证到位插队首                        │
   └──────────────────┴──────────────────────────────────────────┘
                                    │
                                    ▼
                              阶段5(M15 上线保障 · 硬性门禁)
```

**关键路径**：阶段 0 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5。
**可并行支线**：阶段 1（工程化/验收）与阶段 2 并行；US-3.1 多住宅可与阶段 1/2 并行启动；V2.0 与 M15 在补员前提下可重叠。

**排序优先级结论（先做什么）：**
1. **阶段 0 全部（B0/B1/B2/T-02）**——无外部依赖、风险最高（不可编译=不可交付），必须第一。
2. **阶段 1 工程化（T-06/T-01/T-05）**——提升可运维性与可提审性。
3. **阶段 2 核心闭环（T-04 + T-03[凭证到位]）**——商业价值最高。
4. **阶段 3 端到端联调 + 埋点**——可用性收口，为智能化铺数据。
5. **阶段 4 V2.0**——体验扩展。
6. **阶段 5 M15**——上线闸门。
