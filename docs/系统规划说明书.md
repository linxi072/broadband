## 1. 项目背景

宽带业务管理系统面向「宽带运营商 / 装维服务商」三位一体业务，覆盖从「下单 → 支付 → 智能派单 → 装机 → SLA 评估/赔付 → 评价 → 退款/开票 → 故障报修」的完整业务闭环：

- **终端客户**：报装、续费、提速、报修、评价、账单；
- **装维师傅**：接单、施工、完工、测速、报修处理；
- **运营后台**：订单、客户、套餐、派单、SLA、财务、权限、字典配置。

**愿景**：打造覆盖「销售—装维—运营」全链路的宽带业务平台，以可安装性校验、智能派单、装维 SLA 赔付、套餐灵活升级与流量透明化为核心竞争力，对标中国电信「美好家/慢必赔」与中国移动「和家庭/超时赔」的最佳实践。

---

## 2. 建设目标

核心目标（SMART 化）：

- **前端办理转化率**：覆盖查询→下单链路可装性实时校验，避免超卖。
- **装维时效**：相邻小区合并派单 + 时段容量管控，超容自动拦截。
- **服务可信**：SLA 规则引擎驱动「慢必赔/不达标赔」自动赔付。
- **经营灵活**：套餐升档/加购在线办理，补差计算透明可追溯。
- **运营可控**：PC 后台全模块可用，权限最小化（21 权限码 + 菜单驱动）。

---

## 3. 系统定位

系统定位为「单体优先、模块收敛」的宽带业务一体化平台，对三类用户统一支撑：

| 用户角色 | 核心诉求 | 端载体 |
|----------|----------|--------|
| 终端客户（C 端） | 查覆盖、下单、升档、报修、评价 | 微信小程序客户端 |
| 装维师傅 | 接单、施工、完工、测速 | 微信小程序师傅端 |
| 运营后台 | 订单/客户/套餐/派单/SLA/财务/权限 | PC 管理后台（web-admin） |

## 4. 技术选型与原则

| 层 | 选型 |
|----|------|
| 后端 | Spring Boot 3.2.1 / JDK 21（单体） |
| ORM | MyBatis-Plus（boot3 starter） |
| 安全 | Spring Security 6 + 自研 HS256 JWT |
| 前端（PC） | Vue 3.5 + Element Plus + Pinia + Vue Router + Vite 5 |
| 前端（小程序） | 微信小程序（双独立工程） |
| 数据库 | MySQL 8.4（启动自动建表，幂等） |
| 监控 | Actuator + Micrometer-Prometheus |
| 部署 | Nginx 反代 + systemd / 容器化 |

**架构原则**：单体优先、模块收敛（后端业务模块上限 5 个）、配置原生（不引 Apollo/注册中心）、零三方安全依赖（自研 JWT）。

## 7. V1.13 交付要点（本轮已落地）

- **故障报修全流程**：`work_order` 新增 `type/ fault_category/ fault_desc/ contact_phone`；新增 `RepairController`（`/api/repair/*`）+ 小程序 3 页（apply/list/detail），复用派单/完工/SLA/评价链路。
- **数据字典**：`sys_dict_type` / `sys_dict_data` + 后台 CRUD（`system:dict`）+ 免鉴权 `/api/dict/public/{type}`，外置硬编码枚举。
- **参数配置**：`sys_config` + 后台 CRUD（`system:config`）+ 免鉴权 `/api/config/public/{key}`，承载客服电话、报修 SLA、派单容量等。
- 接口映射总数约 112（含 62 基线 + 交易闭环 + V1.13 报修/字典/配置）。

## 8. 已知约束与风险

### 8.1 已知约束

- **微信支付**：当前 Mock 桩（`PayService` seam），真集成待商户号/APIv3 凭证。
- **师傅端验收**：8 页已接真实接口，待微信开发者工具真机视觉验收（无浏览器环境）。
- **国际化**：暂未做 i18n。
- **配置动态刷新**：当前多 profile 静态切换，未做运行时热刷新。

### 8.2 风险与对策

| 风险 | 影响 | 对策 | 状态 |
|---|---|---|---|
| 设计稿规划页多、实现面广 | 进度压力 | 垂直切片，先打通核心链路再扩展 | 持续 |
| mock 与真实数据差异 | 联调返工 | 接口契约先行；已修复字段契约不一致 | 已缓解 |
| 师傅端小程序未启动 | 交付不完整 | 集中资源建页；后端容量接口已就绪 | ✅ 已落地（8 页） |
| 容量 / SLA 规则需运营确认 | 业务正确性 | 规则参数化入库，先默认值后调优 | 持续 |
| 多端主题与权限一致性 | 体验 / 安全 | 统一设计 token + RBAC 模型；菜单树后端单一来源 | 已落地 |
| 自研 JWT 的正确性 | 安全 | 零三方依赖换取可审计性，配 7 条回归单测 | 已落地 |
| 生产默认密钥/口令 | 安全 | `app.jwt.secret` 环境变量覆盖；首登强制改密 | 待办（上线前） |
