## 2. V1.11 交易真闭环（本轮交付）

### 2.1 退款 / 对账状态机 ✅

**目标**：在业务订单生命周期中补齐「退款」状态，财务对账口径与实际资金流对齐。

**需求点**

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| R1 | `biz_order.status` 新增 `REFUND` 终态 | schema 注释与枚举覆盖；历史库 ALTER 守卫补齐 |
| R2 | C 端 `POST /api/order/refund` 申请退款 | 仅 PAID/INSTALLING/DONE 可发起；幂等（同单已有 PENDING/REFUNDED 直接返回） |
| R3 | 后台 `GET /api/admin/refunds` 列表（finance:view） | 支持按 status 过滤；返回退款单 + 关联订单 + 金额 + 流水号 |
| R4 | 后台 `POST /api/admin/refunds/{id}/approve` | PENDING→REFUNDED，生成 `refund_no`，并将业务订单置 `REFUND`（营收扣减） |
| R5 | 后台 `POST /api/admin/refunds/{id}/reject` | PENDING→REJECTED |
| R6 | 财务对账口径对齐 | `finance/report`：revenue=PAID/INSTALLING/DONE；refund=REFUND（真退款）；cancelled=CANCELLED（取消不计营收）；营销汇总排除 REFUND |

**数据模型**

```sql
CREATE TABLE order_refund (
  id, order_id, order_no, customer_id, customer_name, amount,
  reason, channel, status,            -- PENDING/APPROVED/REJECTED/REFUNDED
  refund_no, operator, created_time, handled_time
);
```

**状态机**

```
C端申请           财务审批
PENDING ──────► APPROVED ──────► REFUNDED（同时 biz_order.status=REFUND）
   │
   └──────────────────────────► REJECTED
```

### 2.2 电子发票占位（开票申请 + 状态）✅

**目标**：提供电子发票的申请与开票流转闭环（占位实现，真实发票平台接入后仅替换 `pdf_url` 与开票动作）。

**需求点**

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| I1 | C 端 `POST /api/invoice/apply` | 仅 DONE 订单可开；幂等；写入 `invoice_apply`(PENDING) |
| I2 | C 端 `GET /api/invoice/my` | 按客户名查询本人发票申请与状态 |
| I3 | 后台 `GET /api/admin/invoices` | 列表 + 按 status 过滤 |
| I4 | 后台 `POST /api/admin/invoices/{id}/open` | PENDING→OPENED，生成 `invoice_no` + 占位 `pdf_url` |
| I5 | 后台 `POST /api/admin/invoices/{id}/reject` | PENDING→REJECTED（记驳回原因） |

**状态机**：`PENDING → OPENED / REJECTED`，`pdf_url` 为占位地址，真实接入后回填。

### 2.3 师傅完工自动生成「服务评价」推送（评价闭环增强）✅

**目标**：师傅完工后系统自动向客户推送一条「待评价」，客户回填评分闭环评价。

**需求点**

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| E1 | `WorkerController.complete()` 完工后 | 自动向 `review` 插入一条 `status=TO_EVALUATE` 记录（order_id=业务订单，customer/worker 名取自工单） |
| E2 | 幂等 | 同一订单已有 TO_EVALUATE 则不重复插入 |
| E3 | C 端 `POST /api/review/submit/{reviewId}` | 客户对 TO_EVALUATE 回填 score/tags/content → `status=PENDING`（进入原评价处理流） |

**闭环**：`完工(DONE)` → `系统推送 TO_EVALUATE` → `客户回填` → `PENDING（待客关/客服处理）`。
