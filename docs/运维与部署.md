## 1. 部署架构

系统采用**单体**架构（非微服务），不引入注册中心 / 配置中心（Apollo）。后端为单个 Spring Boot 应用，前端与小程序通过 Nginx 反向代理同源访问后端 8082 端口。配置坚持 Spring Boot 原生（`yml` + 环境变量）。

**系统组成与端口规划**

| 组件 | 技术 | 默认端口 | 说明 |
|------|------|----------|------|
| 后端服务（broadband-backend） | Spring Boot 3.2.1 / JDK 21 | **8082** | 单体应用，全部业务 API |
| MySQL | 8.4.x | **3306** | 库名 `broadband`，账号 `broadband` |
| PC 管理后台（web-admin） | Vue 3.5 + Vite 5 | 构建后由 **Nginx 80/443** 托管；开发态 5173 | 纯静态资源 |
| 微信小程序（客户端 / 师傅端） | 微信原生 | — | 通过 HTTPS 访问后端 8082 |

## 3. 部署步骤（后端 jar + Nginx + 小程序）

### 3.1 数据库初始化（建库与账号，一次性）

后端启动参数带 `createDatabaseIfNotExist=true`，首次启动自动建库；表结构与种子数据由 `db/schema.sql` + `db/data.sql` 启动自动执行（幂等）。也可手工建库授权：

```sql
-- 以管理员账号执行
CREATE DATABASE IF NOT EXISTS broadband DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER IF NOT EXISTS 'broadband'@'%' IDENTIFIED BY '<你的密码>';
GRANT ALL PRIVILEGES ON broadband.* TO 'broadband'@'%';
FLUSH PRIVILEGES;
```

> **表结构无需手工创建**：应用启动时会执行 `db/schema.sql`（`CREATE TABLE IF NOT EXISTS`）与 `db/data.sql`（`INSERT IGNORE`），幂等且不会覆盖运行期新增数据。

手动初始化（如需独立执行）：

```bash
mysql -u<user> -p < broadband < backend/src/main/resources/db/schema.sql
mysql -u<user> -p < broadband < backend/src/main/resources/db/data.sql
```

### 3.3 后端启动（生产姿态，单 JVM）

> ⚠️ **禁止** `mvn spring-boot:run` 用于生产验证：本沙箱中该方式会被注入随机端口（fork JVM）。
> 必须用 `java -jar` 显式指定端口，程序参数优先级最高。

```bash
export DB_HOST=127.0.0.1
export DB_PORT=3306
export DB_NAME=broadband
export DB_USERNAME=broadband
export DB_PASSWORD=broadband

java -jar target/broadband-backend-1.0.0.jar --server.port=8082
```

> ⚠️ **端口优先级坑**：命令行 `--server.port` > 环境变量 > `application.yml`。
> 若宿主机/沙箱注入了 `SERVER_PORT` 之类的变量导致端口不是你期望的，请显式加 `--server.port=8082`。

多环境 Profile（`application.yml` 仅放公共配置；环境差异在 `application-dev.yml` / `application-prod.yml`）：

```bash
# 生产
java -jar broadband-backend-1.0.0.jar --spring.profiles.active=prod --server.port=8082
```

环境变量注入优先级：`命令行参数 > 环境变量 > application-prod.yml > application.yml`。

### 3.4 冒烟验证

```bash
B=http://127.0.0.1:8082

# 1) 未带 token → 期望 401
curl -s -o /dev/null -w "%{http_code}\n" "$B/api/sla/rules"

# 2) 登录取 token
TOK=$(curl -s -X POST "$B/api/auth/login" -H 'Content-Type: application/json' \
      -d '{"username":"admin","password":"admin123"}' \
      | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# 3) 带 token 取菜单树与权限码
curl -s -H "Authorization: Bearer $TOK" "$B/api/auth/me" | head -c 400

# 4) 业务数据
curl -s -H "Authorization: Bearer $TOK" "$B/api/admin/dashboard/stats"
curl -s -H "Authorization: Bearer $TOK" "$B/api/sla/board"
curl -s -H "Authorization: Bearer $TOK" "$B/api/admin/orders?page=1"

# 5) 越权（财务账号访问 SLA）→ 期望 403
FT=$(curl -s -X POST "$B/api/auth/login" -H 'Content-Type: application/json' \
     -d '{"username":"zhaomin","password":"zhaomin123"}' \
     | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $FT" "$B/api/sla/rules"
```

### 3.5 前端（web-admin）构建与 Nginx 托管

```bash
cd web-admin
npm install --registry=https://registry.npmmirror.com
npm run build            # 产出 dist/
```

开发态：`npm run dev`（http://127.0.0.1:5173，`VITE_API_TARGET` 指向后端，Vite 代理 `/api` 到 8082）。`.env.development` / `.env.production` 可配置 `VITE_API_TARGET`、`VITE_APP_TITLE`、`VITE_ALLOW_DEMO_LOGIN`。

Nginx 反代示例（部署文档口径，root 视实际路径调整）：

```nginx
server {
    listen 80;
    root /var/www/web-admin/dist;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ {
        proxy_pass http://127.0.0.1:8082/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Nginx 反代示例（操作说明书口径，含 SPA history 回落与完整头）：

```nginx
server {
    listen 80;
    server_name bb.example.com;

    root /opt/broadband/web-admin/dist;
    index index.html;

    # SPA history 路由：未命中的路径回落到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端反代（同源，因此生产无需 CORS）
    location /api/ {
        proxy_pass http://127.0.0.1:8082;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

> 登录页使用 `admin / admin123`。若后端不可达且 `VITE_ALLOW_DEMO_LOGIN=true`，会降级为本地演示登录（页头标注演示态）。

**后端进程**：建议 systemd 托管（`ExecStart` 用绝对路径 `java -jar`，`Environment=` 注入 `DB_*` 与 `JWT_SECRET`），或容器化；`--server.port=8082` 显式指定更稳妥。生产强制在反代层启用 HTTPS。

## 4. 配置说明（yml / 环境变量 / DB_USERNAME 覆盖）

`backend/src/main/resources/application.yml`（摘录，实际以仓库为准）：

```yaml
server:
  port: 8082

spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    # createDatabaseIfNotExist=true：库不存在时自动创建
    url: jdbc:mysql://${DB_HOST:127.0.0.1}:${DB_PORT:3306}/${DB_NAME:broadband}?createDatabaseIfNotExist=true&useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${DB_USERNAME:root}
    password: ${DB_PASSWORD:}
  sql:
    init:                                   # 启动执行幂等脚本，不覆盖运行期数据
      mode: always
      schema-locations: classpath:db/schema.sql
      data-locations: classpath:db/data.sql

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true      # packageId -> package_id

app:
  jwt:
    secret: ${JWT_SECRET:broadband-rbac-secret-please-change-in-production}   # ⚠️ 生产必须覆盖
    ttl-minutes: 120
  security:
    protect-client-api: false               # true = 小程序 c 端接口也强制鉴权
  wechat:
    worker:                                 # 师傅端独立小程序凭证位
      appid: ${WECHAT_WORKER_APPID:}
      secret: ${WECHAT_WORKER_SECRET:}
```

> 数据源用户名通过 `DB_USERNAME` 环境变量覆盖（默认值 `root`）。生产务必用环境变量注入 `DB_USERNAME` / `DB_PASSWORD` / `JWT_SECRET`，**不要写进代码仓库**。`yml` 中 `username: ${DB_USERNAME:root}` 仅作兜底，实际生效值以注入的环境变量为准。

**环境变量清单**

| 变量 | 默认值 | 说明 |
|---|---|---|
| `DB_HOST` / `DB_PORT` / `DB_NAME` | `127.0.0.1` / `3306` / `broadband` | 数据源 |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / 空 | **不要写进代码仓库**；`DB_USERNAME` 覆盖 yml 默认 |
| `JWT_SECRET` | 开发用默认串 | 生产必须替换为高强度随机串 |
| `WECHAT_APPID` | `wxcc344ad7f4f849d4` | 客户端小程序 AppID（公开标识，已回填真实值） |
| `WECHAT_SECRET` | 空 | 客户端小程序 AppSecret，**生产用环境变量注入，yml 不落明文** |
| `WECHAT_WORKER_APPID` | 空 | **师傅端小程序（broadband-worker）独立 AppID**，提审前在微信公众平台新注册并注入（勿与客户端共用） |
| `WECHAT_WORKER_SECRET` | 空 | 师傅端小程序 AppSecret，预留给后续师傅端启用微信登录 / 订阅消息能力时注入 |
| `SERVER_PORT` | — | 注意与命令行 `--server.port` 的优先级关系 |

> 按既定架构决策：**不引入 Apollo 等外部配置中心**，配置走 yml + 环境变量。

### 4.1 微信小程序登录（code2Session）与演示态切换

客户端小程序登录走 `POST /api/auth/miniapp-login`：

- **未注入 `WECHAT_SECRET`**（默认）→ 后端 `WechatMiniAppService.configured()` 为 false，自动回退**演示分支**：手机号 + 固定验证码 `1234`，签发演示 JWT（`wechatBound=false`）。本地无真实凭证也可联调。
- **注入 `WECHAT_SECRET`** → `configured()` 为 true，自动切换**真实路径**：用小程序 `wx.login()` 换取的临时 `code` 调微信 `jscode2session` 换取 `openid`，按 `openid` 查/绑客户，签发真实 JWT（`wechatBound=true`）。**前端无需改动**——客户端 `pages/login` 已集成 `wx.login()`，并把真实 `code` 上送、演示码放在 `smsCode` 字段，后端两种模式都能正确识别。

**注入方式（三选一，重启后端生效）**：

```bash
# 方式一：Maven 直接运行
WECHAT_SECRET=你的真实AppSecret mvn spring-boot:run

# 方式二：先打包再以环境变量运行 jar
mvn -q clean package -DskipTests
WECHAT_APPID=wxcc344ad7f4f849d4 WECHAT_SECRET=你的真实AppSecret \
  java -jar target/broadband-backend-1.0.0.jar

# 方式三：Docker / systemd 在环境侧注入同名环境变量即可
```

> 师傅端（`broadband-worker`）走独立的 `POST /api/auth/worker-login`，按手机号鉴权、**不依赖微信 openid**，因此不受 `WECHAT_SECRET` 影响，始终为手机号 + 演示码 `1234`（生产应替换为真实短信网关校验）。
>
> 客户端接口当前属**开放层**（未强制鉴权，设计有意保留）。如需强制全体鉴权，将 `app.security.protect-client-api` 置为 `true` 即可统一收口（`request()` 已就绪，无需改页面）。目前登录已接入真实 `miniapp-login`，但 c 端业务接口仍对匿名放行。

### 4.2 账号与权限

初始密码由 `RbacInitializer` 在首次启动时以 **BCrypt** 写入（幂等：已有密码不覆盖，因此用户改过的密码不会被启动流程重置）。

| 账号 | 初始密码 | 角色 | 可见菜单 | 权限码 |
|---|---|---|---|---|
| admin | admin123 | ADMIN 超级管理员 | 26 | 21 |
| liuwei | liuwei123 | OPERATOR 运营专员 | 19 | 15 |
| zhaomin | zhaomin123 | FINANCE 财务 | 4 | 4 |
| wangfang | wangfang123 | CS 客服 | 4 | 4 |

> ⚠️ **上线前必做**：① 修改全部默认密码；② 通过 `JWT_SECRET` 覆盖默认密钥；③ 删除或禁用不需要的演示账号。

权限模型：

- 权限码来源唯一：`sys_menu.perm`。三处同源 —— **DB 菜单表 / 后端 `@PreAuthorize("hasAuthority('xxx')")` / 前端路由 `meta.perm`**。
- 角色与权限码**每请求实时查库**（不固化进 token），因此后台调整角色授权后**立即生效，无需重新登录**。
- 授权变更接口：`PUT /api/system/roles/{id}/menus`；用户改角色：`PUT /api/system/users/{id}/roles`。
- 登录失败、越权访问、写操作均记入 `sys_oper_log`，可在后台 `/system/log` 查看。
- 认证：自研 HS256 JWT，零三方依赖；令牌含 `dept`（CUSTOMER / WORKER / ADMIN 类）。数据权限：运营按 `dept_id` 含下级过滤，admin（`dept_id` 空）看全量。

### 4.3 数据库说明（MySQL 8.4 / 25 张表）

**初始化方式**：随应用启动自动执行 `db/schema.sql` + `db/data.sql`（幂等）。
手工执行亦可：`mysql -ubroadband -p broadband < backend/src/main/resources/db/schema.sql`。

> 注：部署文档提及 `schema.sql` 含 28 张表结构（含历史列补齐 ALTER 守卫）；操作说明书列出的业务/权限域为 25 张表。以仓库 `schema.sql` 实际执行为准，脚本幂等。

| 域 | 表 |
|---|---|
| 小区覆盖 | `community`、`community_demand` |
| 派单与装维 | `worker`、`worker_capacity`、`work_order`、`sla_rule`、`sla_record`、`compensation` |
| 套餐与客户 | `package_info`、`package_image`、`package_converge_item`、`package_param`、`package_param_option`、`package_upgrade_order`、`customer`、`customer_contract` |
| 流量与订单 | `traffic_usage`、`biz_order`、`review` |
| 权限域 | `sys_user`、`sys_role`、`sys_menu`、`sys_user_role`、`sys_role_menu`、`sys_oper_log` |

**常用运维 SQL**

```sql
-- 表与行数概览
SELECT table_name, table_rows FROM information_schema.tables
 WHERE table_schema='broadband' ORDER BY table_name;

-- 重复演示派单前，把工单重置为待派（否则上一轮已是 ASSIGNED）
UPDATE work_order SET status='PENDING', worker_id=NULL, cluster_id=NULL, adjacent_route=NULL;

-- 查看最近的越权与登录失败记录
SELECT created_time, username, action, result, ip FROM sys_oper_log
 WHERE result LIKE '失败%' OR action LIKE '%未携带%' ORDER BY id DESC LIMIT 20;
```

> 说明：`package_converge_item.description` 与 `package_param_option.option_value` 两个列名用于规避 SQL 保留字
> （`desc` / `value`），后端在 Mapper 内用 `@Select` 别名桥接为 `desc` / `value` 返回给前端 —— **改列名时务必同步改 Mapper**。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 启动报 `Invalid value type for attribute 'factoryBeanObjectType'` | 用了 `mybatis-plus-boot-starter`（带 `mybatis-spring:2.x`），与 Spring 6.1 不兼容 | 改用 `mybatis-plus-spring-boot3-starter`（`mybatis-spring:3.0.3`） |
| **登录成功、token 正确，但所有受保护接口一律 401** | ① `JwtUtil` 解析异常被过滤器静默吞掉；② token 密钥与签发密钥不一致 | 打开 `--logging.level.com.broadband.system.security=DEBUG`，看 `JWT 鉴权失败 uri=... 原因=...`；已修复历史缺陷：数字声明扫描需按 0–9 判定 |
| 400/401 之外返回 `{"code":500,"message":"服务端异常：DataIntegrityViolationException"}` | 多表联查 `SELECT id` 未加表别名 → `Column 'id' in field list is ambiguous` | 给联表查询的列**全部加表别名**（如 `o.id`、`pkg.name`） |
| 启动后端口不是 8082 | 宿主机/沙箱注入了 `SERVER_PORT` 环境变量 | 命令行显式 `--server.port=8082`（优先级最高） |
| 服务启动即退出（非 kill） | `spring.sql.init` 脚本执行失败（`continue-on-error: false`）或数据源连不上 | 看启动日志中 `schema.sql` / `data.sql` 附近的异常；校验 `DB_*` 与账号建表权限 |
| `javac` 报 `程序包 com.baomidou 不存在` | 误编译了 `mapper/`、`spring/` 目录 | 按 §7.4 命令排除 `mapper/`、`spring/` |
| `command not found: mvn` | Maven 未加入 PATH | 用绝对路径 `~/Documents/localRepository/devRepository/maven/bin/mvn` |
| 前端 `npm install` 极慢 | 默认走 `registry.npmjs.org` | 可切镜像：`npm config set registry https://registry.npmmirror.com` |
| 前端页面显示「演示数据」 | 接口不可达 / 返回 404，触发了兜底 | 确认后端已启动且 `/api` 代理指向正确端口；健康链路下会自动走真实数据 |
| 小程序请求失败 | `baseUrl` 未配置 / 不在同一网络 | 配 `globalData.baseUrl`；本地联调用 `http://<本机IP>:8082` |
| 派单全超容 | 单师傅时段容量上限过低 | 调整 `worker_capacity`（相邻 3–4 / 非相邻 1–2）或 `CapacityPolicy` 策略常量 |
| 重复派单无效果 | 工单已是 `ASSIGNED` | 先执行 §4.3 的工单重置 SQL |
| 越权却返回 401（而非 403） | 说明认证就没通过（token 无效/过期），不是权限问题 | 先按 401 排查；401=未认证，403=已认证但无权限 |
| 启动后立即退出（运维视角） | 数据库连接失败 / 账号密码错 | 核对 `DB_USERNAME/DB_PASSWORD`，确认 `broadband` 库存在 |
| 全部接口 401（`iat/exp` 解析异常） | JWT 声明数字解析缺陷（已修复） | 升级到含修复的版本 |
| 派单容量异常 | 小区相邻性未识别 | 核查 `community.street` / 经纬度 |
| 报表数据为空 | 数据权限行级隔离过滤 | 用 admin（无部门）核对 `dept_id` 归属 |

## 9. 数据备份与恢复

| 对象 | 频率 | 方式 |
|------|------|------|
| MySQL | 每日全量 + 增量 binlog | `mysqldump` / 云 RDS 自动备份 |
| 应用 jar | 随发版归档 | 制品库（镜像 tag） |
| 静态资源 | 随发版 | 对象存储 / CDN |

RTO < 30min，RPO < 5min（binlog）。

**备份示例**

```bash
# 逻辑全量备份（每日）
mysqldump -ubroadband -p --single-transaction --routines --events \
  broadband > /backup/broadband_$(date +%F).sql

# 恢复
mysql -ubroadband -p broadband < /backup/broadband_YYYY-MM-DD.sql
```

> 说明：数据库 schema 向后兼容（仅追加列，不删改），回滚 jar 时无需回退数据。应用 jar 保留最近 3 个版本用于回滚（见 §7.3）。

**安全基线补充**：传输层生产强制 HTTPS（反向代理层启用）；审计 `sys_oper_log` 记录关键操作。
