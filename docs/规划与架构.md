# 宽带业务管理系统 · 规划与架构

> 本文档合并《系统规划说明书》（v1.4）与《系统架构说明书》（V1.0.1 + V1.11 交易真闭环），统一阐述系统的规划路线、建设目标、整体架构、模块职责、部署拓扑与非功能设计，作为两份原始文档的替代与合订本。两源在接口数、表数、前端页量等存在演进差异，已在相关章节以「规划 / 架构」双口径标注，以反映从 Phase 3 收口到 V1.11 交易闭环的增量。

---

## 1. 项目背景

宽带业务管理系统面向「宽带运营商 / 装维服务商」三位一体业务，覆盖从「下单 → 支付 → 智能派单 → 装机 → SLA 评估/赔付 → 评价 → 退款/开票」的完整业务闭环：

- **终端客户**：报装、续费、提速、报修、评价；
- **装维师傅**：接单、施工、完工、测速；
- **运营后台**：订单、客户、套餐、派单、SLA、财务、权限。

**愿景**：打造覆盖「销售—装维—运营」全链路的宽带业务平台，以可安装性校验、智能派单、装维 SLA 赔付、套餐灵活升级与流量透明化为核心竞争力，对标中国电信「美好家/慢必赔」与中国移动「和家庭/超时赔」的最佳实践。

---

## 2. 建设目标

核心目标（SMART 化）：

- **前端办理转化率**：覆盖查询→下单链路可装性实时校验，避免超卖。
- **装维时效**：相邻小区合并派单 + 时段容量管控，超容自动拦截。
- **服务可信**：SLA 规则引擎驱动「慢必赔/不达标赔」自动赔付。
- **经营灵活**：套餐升档/加购在线办理，补差计算透明可追溯。
- **运营可控**：PC 后台全模块可用，权限最小化（21 个权限码 + 菜单驱动）。

---

## 3. 系统定位

系统定位为「单体优先、模块收敛」的宽带业务一体化平台，对三类用户统一支撑：

| 用户角色 | 核心诉求 | 端载体 |
|----------|----------|--------|
| 终端客户（C 端） | 查覆盖、下单、升档、报修、评价 | 微信小程序客户端 |
| 装维师傅 | 接单、施工、完工、测速 | 微信小程序师傅端 |
| 运营后台 | 订单/客户/套餐/派单/SLA/财务/权限 | PC 管理后台（web-admin） |

---

## 4. 技术选型

| 层 | 选型 | 说明 |
|----|------|------|
| 后端 | Spring Boot 3.2.1 / JDK 21（单体） | 单体应用，业务模块上限 5 个 |
| ORM | MyBatis-Plus（`mybatis-plus-spring-boot3-starter`） | Model 零注解，主键 `Ids.next()` 显式生成 |
| 安全 | Spring Security 6（`STATELESS`）+ 自研 HS256 JWT | 零三方安全依赖，授权每请求实时查库 |
| 前端（PC） | Vue 3.5 + Element Plus + Pinia + Vue Router + Vite 5 | 主题靛 `#4f46e5` |
| 前端（小程序） | 微信小程序（双独立工程） | 客户端蓝 `#2563eb` / 师傅端橙 `#ea580c` |
| 数据库 | MySQL 8.4 | 启动自动建表（幂等），不覆盖运行期数据 |
| 监控 | Actuator + Micrometer-Prometheus | 开放 `/actuator/prometheus`（HTTP/JVM/GC/线程） |
| 部署 | Nginx 反代 + systemd / 容器化 | `/api → :8082`，静态资源直出 |

**架构原则**：单体优先、模块收敛（后端业务模块上限 5 个）、配置原生（不引 Apollo/注册中心）、零三方安全依赖（自研 JWT）。

## 6. 模块划分与职责

### 6.1 后端模块（Spring Boot 单体）

| 模块 | 职责 | 关键能力 |
|------|------|----------|
| `community` | 小区覆盖、覆盖需求登记 | 覆盖查询、需求登记（C 端开放） |
| `install` | 智能派单 + 装维 SLA | 容量规则引擎、并查集聚类、贪心派单、SLA 时限/速率双评估、赔付 |
| `product` | 套餐/订单/客户/升级/流量/评价/发票 | 套餐升级引擎、流量查询、业务闭环、客户 360、营销看板、退款/发票 |
| `system` | RBAC / 平台聚合 / 部门 | 自研 JWT、用户/角色/菜单 CRUD、CSV 导入导出、数据权限行级隔离 |
| `common` | 公共层 | Ids 生成、全局异常、统一响应 |

> 聚合类接口归入 `system` 的「平台聚合」（`AdminPlatformController`）与 `product` 的 `AdminProductController`，保持模块单向可拆。

### 6.2 关键技术决策

- **安全**：Spring Security 6（`STATELESS`）+ 自研 HS256 JWT（零三方依赖）；`JwtAuthFilter` 按 `dept` 建立 CUSTOMER / WORKER / ADMIN 身份。
- **权限同源**：21 权限码 / 5 角色 / 26 菜单，在「DB ↔ `@PreAuthorize` ↔ 前端 `meta.perm`」三处强制一致。
- **配置**：Spring Boot 原生（yml + 环境变量），多 profile（dev/prod），不引入 Apollo；规则参数以库内参数化 + 环境变量覆盖为准。
- **监控**：Actuator + Micrometer-Prometheus，开放 `/actuator/prometheus`。

### 6.3 前端架构

**PC 管理后台（web-admin）**

- 技术：Vue 3.5 + Element Plus（按需引入）+ Pinia + Vue Router + Vite 5。
- 规模：28 个 `.vue` 页面（23 条路由），主题靛 `#4f46e5`（CSS 变量收敛）。
- 导航：`navConfig` 驱动侧边栏，按 `user.perms` 过滤；路由守卫按 `to.meta.perm` 校验。
- 降级：后端不可达时页面降级内置「演示数据」并标 `SourceTag`。
- 详情类路由（如客户 360 `/customer/:id`）只加在 `router/index.js` 的 children，不进 `navConfig`，避免污染菜单。

**微信小程序（双独立工程）**

- 客户端 `broadband-miniapp/`：蓝 `#2563eb`，15 页（含登录）。
- 师傅端 `broadband-worker/`：橙 `#ea580c`，8 页，全接真实接口（含 401 门禁）。
- 登录态：手机号 + 验证码（演示 `1234`）→ `POST /api/auth/miniapp-login` 拿真实 token → `globalData` + Storage；`api.request()` 注入 Bearer。

## 7. 数据模型

共 **28 张表**（规划基线 25 张，V1.11 交易真闭环新增退款/发票相关表），分组如下：

| 域 | 代表表 |
|----|--------|
| 小区/覆盖 | `community`, `community_demand` |
| 装维 | `work_order`, `worker`, `worker_capacity`, `sla_rule`, `sla_record`, `compensation`, `dispatch_*` |
| 订单/交易 | `biz_order`, `order_refund`（V1.11 新增）, `invoice_apply`（V1.11 新增） |
| 客户/套餐 | `customer`, `customer_contract`, `package_info`, `package_*`, `package_upgrade_order` |
| 评价 | `review`（含 V1.11 `TO_EVALUATE` 状态） |
| 权限 | `sys_user`, `sys_role`, `sys_menu`, `sys_role_menu`, `sys_user_role`, `sys_department`, `sys_oper_log` |

**V1.11 数据扩展**：

- `biz_order.status` 增加 `REFUND` 终态（退款营收扣减）。
- `review.status` 增加 `TO_EVALUATE`（系统推送待评价）。
- 新增 `order_refund`、`invoice_apply` 两张事务表。

## 8. 核心业务流程

### 8.1 业务主闭环

```
下单(PENDING) → 支付(PAID, 生成安装工单)
  → 智能派单(容量校验: 相邻3-4/非相邻1-2) → 师傅施工(INSTALLING)
  → 完工(DONE, 自动 SLA 评估 + 自动推送 TO_EVALUATE 待评价)
  → 客户评价(PENDING) → SLA 不达标自动赔付(compensation)
```

### 8.2 退款状态机（V1.11）

```
C端申请           财务审批
PENDING ──────► APPROVED ──────► REFUNDED（biz_order.status=REFUND）
   └─────────────────────────► REJECTED
```

### 8.3 电子发票（V1.11 占位）

```
C端申请(PENDING) ──► 财务开具(OPENED, 生成 invoice_no + pdf_url 占位)
                  └──► 驳回(REJECTED)
```

## 10. 非功能需求

### 10.1 维度方案

| 维度 | 方案 |
|------|------|
| 安全 | 自研 HS256 JWT；RBAC + 数据权限行级隔离；`sys_oper_log` 审计 |
| 性能 | 容量规则在内存聚类；k6 压测 20→50 VU，P95 < 800ms、失败率 < 1% |
| 可观测 | Actuator/Prometheus 指标 + 告警规则（时延/错误率/堆） |
| 可维护 | 单体模块上限 5；配置原生；CI/CD 构建+单测+镜像 |
| 兼容 | DB schema 仅追加列不删改，支持平滑升级 |

### 10.2 性能与安全指标

- **压测基线**：k6 由 20 VU 提升至 50 VU，P95 < 800ms，失败率 < 1%。
- **鉴权矩阵**（已实测）：无 token → 401、越权 → 403、授权内 → 200；登录失败 / 越权 / 写操作均落审计日志。
- **容量规则**：相邻小区 3–4 单、非相邻 1–2 单，超容自动拦截。
- **自检**：JWT 自研零三方依赖，配 7 条回归单测（`JwtUtilTest`）保障正确性。

## 11. 技术约束与演进

### 11.1 规划原则

1. **算法与框架解耦**：核心算法保持纯 Java 可独立验证，降低回归风险。
2. **接口先行、契约稳定**：REST 接口契约先定义，前后端并行开发。
3. **垂直切片交付**：按业务域（community / install / product / system）逐模块打通「接口 → 前端 → DB」。
4. **基础设施按需后置**：DB / 安全按阶段接入；明确不引入的能力就不做半成品（不引入 Spring Cloud、不引入 Apollo）。

### 11.2 技术演进路线

| 能力 | 现状（v1.1） | 目标 |
|---|---|---|
| 数据层 | ✅ MySQL 8.4 单库，25 表，启动自动建表 | 按量再评估读写分离 / 缓存 |
| 安全 | ✅ RBAC + JWT + 操作审计（21 权限码，5 角色） | 数据行级权限、登录风控 |
| 配置 | ✅ `application.yml` + 环境变量；规则参数入库 | 参数在线维护界面（不做外部配置中心） |
| 前端 | ✅ PC 后台 22 业务页；✅ 客户端 20 页 + 师傅端 8 页（含登录态骨架） | 登录态正式接入后端鉴权 |
| 监控 | 🟡 内置轻量指标 + 操作日志 | Prometheus + 日志中心 + 告警 |
| 部署 | 🟡 本地 jar + Vite | Nginx + 容器化 + CI/CD |

### 11.3 已知约束

- **微信支付**：当前 Mock 桩（`PayService` seam），真集成待商户号/APIv3 凭证。
- **师傅端验收**：8 页已接真实接口，待微信开发者工具真机视觉验收。
- **国际化**：暂未做 i18n。
- **配置动态刷新**：当前多 profile 静态切换，未做运行时热刷新。

### 11.4 风险与对策

| 风险 | 影响 | 对策 | 状态 |
|---|---|---|---|
| 设计稿规划页多、实现面广 | 进度压力 | 垂直切片，先打通核心链路再扩展 | 持续 |
| mock 与真实数据差异 | 联调返工 | 接口契约先行；已在 Phase 2 暴露并修复 2 处字段契约不一致 | 已缓解 |
| 师傅端小程序未启动 | 交付不完整 | Phase 4 集中资源建页；后端 `worker_capacity` 与容量接口已就绪，无阻塞 | ✅ 已落地（8 页） |
| 容量 / SLA 规则需运营确认 | 业务正确性 | 规则参数化入库，先默认值后调优；不做外部配置中心以降低运维面 | 持续 |
| 多端主题与权限一致性 | 体验 / 安全 | 统一设计 token（蓝/橙/靛）与 RBAC 模型；菜单树由后端单一来源下发 | 已落地 |
| 自研 JWT 的正确性 | 安全 | 零三方依赖换取可审计性，但必须配回归单测（已补 7 条）；catch 必须留日志 | 已落地 |
| 生产默认密钥/口令 | 安全 | `app.jwt.secret` 环境变量覆盖；首登强制改密；README/运维手册明示 | 待办（上线前） |
