## 1. 系统定位

宽带业务管理系统面向「宽带办理 + 装维运营」业务场景，覆盖三类使用者：

| 角色 | 载体 | 主题色 | 核心职责 |
|---|---|---|---|
| 客户端（C 端用户） | 微信小程序 | 蓝 `#2563eb` | 选套餐、查覆盖、下单、升档、流量监控、报修 |
| 安装师傅（装维） | 微信小程序（师傅端） | 橙 `#ea580c` | 接单、排班、路线、完工确认、测速 |
| 运营/管理（B 端） | PC 后台（web-admin，规划中） | 靛 `#4f46e5` | 套餐/小区/工单/权限/性能/SLA 看板管理 |

> 当前已落地：**客户端小程序骨架（7 页）+ 后端 5 个业务模块核心代码 + 算法 Demo**。
> 规划中：**PC 后台 web-admin（Vue3 + Element Plus）**、**数据库接入**、**RBAC/Spring Security**、**Apollo 配置中心**。

## 2. 总体架构

```
┌─────────────────────────────── 用户终端层 ───────────────────────────────┐
│  微信小程序（客户端）        微信小程序（师傅端）         PC 后台(规划)    │
│  pages/index service ...     pages/worker ...         Vue3+ElementPlus   │
└───────────────┬───────────────────────┬───────────────────┬─────────────┘
                │  HTTPS / JSON          │                   │
┌───────────────┴───────────────────────┴───────────────────┴─────────────┐
│                          接入层（API Gateway / Nginx，规划）              │
└───────────────────────────────────────┬─────────────────────────────────┘
                                        │  /api/*
┌───────────────────────────────────────┴─────────────────────────────────┐
│                       业务服务层（Spring Boot 3.2.1）                    │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌───────┐ ┌─────────┐             │
│  │community│ │ dispatch│ │  pkg    │ │ sla   │ │ traffic  │  …（同构模块）│
│  │小区覆盖 │ │ 派单算法│ │套餐/升级│ │SLA赔付│ │流量监控 │              │
│  └────┬────┘ └────┬────┘ └────┬────┘ └───┬───┘ └────┬────┘             │
│       └──────────┼────────────┼──────────┼──────────┘                  │
│            统一分层：model / engine / mapper / spring / *Demo            │
└───────────────────────────────────────┬─────────────────────────────────┘
                                        │  MyBatis-Plus
┌───────────────────────────────────────┴─────────────────────────────────┐
│                      数据层（规划：MySQL/PostgreSQL/Oracle）              │
│  community / worker / worker_capacity / work_order                      │
│  sla_rule / sla_record / compensation                                   │
│  package* / traffic_usage / package_upgrade_order                       │
└─────────────────────────────────────────────────────────────────────────┘
```

**各层职责**
- **终端层**：负责界面与交互，通过 `utils/api.js` 统一封装请求；后端未就绪时走 mock 兜底，前后端解耦并行开发。
- **接入层**（规划）：HTTPS 终止、鉴权、限流、路由；当前阶段可直连后端 `:8082`。
- **业务服务层**：按业务域拆分为独立模块，每个模块遵循「纯 Java 引擎可独立验证 + Spring 适配层组装」的同构设计。
- **数据层**：MyBatis-Plus Mapper 对接关系库；当前 Demo 与 Controller 以 mock 返回为主，接库后只需补充数据源与驱动。

## 4. 后端模块划分

后端根路径：`backend/src/main/java/com/broadband/`，共 5 个业务模块、约 72 个 Java 文件。

## 5. 同构分层设计（关键约定）

每个业务模块采用一致的分层，便于维护与替换数据源：

```
com.broadband.{community|install|product}/
├── <Module>Demo.java        # 纯 Java 可独立运行验证（无 Spring 依赖）
├── model/                   # 纯 POJO / VO / 实体（与 DB 表对应）
├── engine/                  # 核心算法（纯 Java，可单测/可独立运行）
├── mapper/                  # MyBatis-Plus Mapper 接口
└── spring/                  # ServiceApi / ServiceImpl / Controller
```

**约定**
- `engine` 不依赖 Spring，输入/输出为纯对象，可 `javac` + `java` 单独验证（见运维文档）。
- `spring` 层只做「组装 DB 数据 → 调用 engine → 落库/返回」，不含业务判断。
- 未接 DB 时，Controller/Service 以 mock 数据返回，前端可并行联调。

## 8. 关键设计决策

1. **算法与框架解耦**：核心算法（派单、SLA、补差、流量）均为纯 Java `engine`，可脱离 Spring 单独编译运行与单测，降低验证成本。
2. **mock 优先、前后端并行**：未接 DB 时 Controller 返回 mock，小程序通过 `api.js` 兜底，两端可同步开发。
3. **派单调度容量策略**：相邻小区（同街道或距离 ≤ 800m）每时段 3–4 单、非相邻 1–2 单；并查集聚类后按容量贪心派单，超出即拦截。
4. **SLA 规则引擎**：时限类（承诺=受理/预约+承诺小时−宽限）与速率类（测速≥最低速率）双模型；赔付按 `PER_ORDER` 或 `PER_OVERTIME_HOUR` 计算并封顶。
5. **升档补差公式**：`月差 = 目标带宽加价 + 增值加价`；`一次性补差 = 月差 × 合约剩余月数(30天/月)`；`新月费 = 当前月费 + 月差`。
6. **流量阈值提醒**：`remaining = total − used`，`warn = remaining ≤ 5`（G），触发加购建议。

## 9. 安全与权限（规划）

- 采用 **RBAC + Spring Security 6 + JWT**；角色与管理端菜单权限树已在设计稿对齐。
- 用户/角色/菜单权限表（`sys_user` / `sys_role` / `sys_menu` / `sys_user_role` / `sys_role_menu`）规划中。
- 小程序端以 openid/session 换取 token；PC 后台以账号密码登录换取 token。

## 10. 前端架构（小程序）

- 结构：`app.js/json/wxss` + `pages/*` + `utils/api.js` + `project.config.json`。
- `utils/api.js`：统一请求封装，路径与后端接口一一对应；后端不可达时页面走本地 mock。
- 已注册 7 个页面：`index / service / package-detail / package-upgrade / community-query / order-address / traffic`。
- 设计稿规划客户端 20 页、师傅端 8 页；当前为骨架态，未建页面以 toast「功能建设中」兜底。

## 11. 外部依赖与演进（规划）

- **Apollo 配置中心**：用于动态下发容量阈值、SLA 规则、特征开关，支持热刷新与动态 namespace。
- **消息/监控**：接入 Prometheus + 日志中心（规划）；当前以控制台日志 + Demo 验证为主。
- **PC 后台 web-admin**：Vue3 + Element Plus + Pinia + Vue Router + Vite，路由 `/dashboard` 起，对接上述后端接口。
