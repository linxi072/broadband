## 七、可复用经验与流程改进

1. **幻影交付防护（最重要的教训）**：跨轮次新建文件可能因沙箱持久化问题「声称写入却未落盘」。**任何「已完成」结论都须先 Glob/文件实测复核**，再对外承诺。本轮即对 v1.15~v1.21 全部控制器、前端页面、CI/DEP/k6 做了磁盘复核，确认无幻影。
2. **路线图文档须与磁盘状态同步**：本轮发现 `后续开发路线规划_v1.16+.md` 仍将已落地的 T-05/T-06/M15-CI/M15-DEP 标为 ⬜，且 `source_extracted/docs/` 总览仍停 v1.10。文档滞后会误导 P0 排期。**每次交付后同步更新路线图状态表**。
3. **IDOR 安全范式固化**：C 端接口一律绑定认证主体（`@AuthenticationPrincipal`），禁止信任客户端 `customerId` 参数（`InvoiceController` 范式已贯穿 Points/Account/Repair/Behavior）。
4. **零依赖可插拔设计**：i18n 用纯 `useI18n()` 函数 + 字典（无 vue-i18n 依赖），行为埋点用纯函数聚合（`RecommendController`），均便于离线单测与无打包环境运行。
5. **CI 触发分支静默失效**：曾因 branches 只列 `main/V1.0.1` 导致 V1.0.2 push 完全不触发 CI（不报错、只是不跑）。**新增发布分支必须同步 branches 列表**（已在 ci.yml 注释中标注）。
6. **文档与代码同仓**：顶层 `docs/` 与 git 内 `source_extracted/docs/` 长期双份导致脱节（R5）。建议统一为单一文档源（git 内），避免 B1 推送丢失。
