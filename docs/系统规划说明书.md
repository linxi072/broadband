# 宽带业务管理系统 · 系统规划说明书

> 文档版本：v1.0 ｜ 基于现状：设计稿 v1.9 + 后端 3 模块/13 接口已落地 ｜ 生成日期：2026-09-14
> 目的：明确系统演进路线、阶段目标、技术演进与风险对策，为研发排期与资源投入提供依据。

---

## 1. 愿景与目标

**愿景**：打造一套覆盖「销售—装维—运营」全链路的宽带业务平台，以可安装性校验、智能派单、装维 SLA 赔付、套餐灵活升级与流量透明化为核心竞争力，对标中国电信「美好家/慢必赔」与中国移动「和家庭/超时赔」的最佳实践。

**核心目标（SMART 化）**
- 前端办理转化率：覆盖查询→下单链路可装性实时校验，避免超卖。
- 装维时效：相邻小区合并派单 + 时段容量管控，超容自动拦截。
- 服务可信：SLA 规则引擎驱动「慢必赔/不达标赔」自动赔付。
- 经营灵活：套餐升档/加购在线办理，补差计算透明可追溯。

---

## 2. 规划原则

1. **算法与框架解耦**：核心算法保持纯 Java 可独立验证，降低回归风险。
2. **接口先行、契约稳定**：REST 接口契约先定义（已完成 13 个），前后端并行。
3. **垂直切片交付**：按业务域（community/dispatch/pkg/sla/traffic）逐模块打通「接口→前端→DB」。
4. **基础设施后置**：DB/安全/配置中心在核心业务验证后统一接入，避免 early over-engineering。

---

## 3. 阶段路线图

> 周期以「相对工期」标注（如 2~3 周），实际排期结合资源确认。

### Phase 1 · 核心底座与联调（进行中 → 收口）
- **目标**：后端核心算法 + 接口契约稳定，客户端骨架打通关键链路。
- **范围**：3 模块 13 接口（已完成）；客户端 7 页骨架（已完成）；端到端 mock 联调。
- **关键交付**：设计稿 v1.9、后端 5 个 Demo 验证报告、小程序 7 页骨架。
- **退出标准**：所有接口可通过 Postman/curl 返回结构化 JSON；小程序关键页可本地预览。

### Phase 2 · 数据持久化与真实联调（建议 3~4 周）
- **目标**：从 mock 切真实数据，端到端可用。
- **范围**：
  - 引入数据库驱动（MySQL/PostgreSQL），按《运维操作说明书》建表（约 12 张）。
  - 各模块 mapper 接入，Controller/Service 去除 mock。
  - 小程序 `api.js` 指向真实后端，关闭兜底或仅保留异常兜底。
- **关键交付**：可运行的后端 jar（连库）、数据初始化脚本、联调用例。

### Phase 3 · PC 后台与权限体系（建议 4~6 周）
- **目标**：运营可管理，权限可控。
- **范围**：
  - 搭建 web-admin（Vue3 + Element Plus + Pinia + Vite），路由 `/dashboard`。
  - 落地 16 个后台模块（套餐/小区/工单/SLA/流量/升级/权限/性能…）。
  - 接入 RBAC：Spring Security 6 + JWT，用户/角色/菜单权限表与前端权限树对齐。
- **关键交付**：PC 后台可登录可用、权限树生效、与小程序共用后端接口。

### Phase 4 · 配置中心、监控与智能化（建议 4~6 周）
- **目标**：可运维、可观测、可运营。
- **范围**：
  - Apollo 配置中心：容量阈值、SLA 规则、特征开关动态下发 + 热刷新。
  - 监控：Prometheus + 日志中心，关键指标（派单成功率/超容率/SLA 达标率/流量阈值触发率）看板。
  - 智能化：派单路径优化、SLA 风险预测、流量套餐智能推荐。
- **关键交付**：配置热更新、监控大盘、运营报表。

## 4. 技术演进路线

| 能力 | 现状 | 目标（Phase 4） |
|---|---|---|
| 数据层 | mock | 多数据源 + 读写分离 |
| 安全 | 无 | RBAC + JWT + 审计日志 |
| 配置 | 硬编码常量 | Apollo 动态配置 + 热刷新 |
| 前端 | 小程序骨架 7 页 | 小程序 20 页 + PC 后台 16 模块 |
| 监控 | 控制台日志 | 指标 + 日志 + 告警 |
| 部署 | 本地 jar | 容器化 + CI/CD + 灰度 |

---

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 设计稿规划页多、实现面广 | 进度压力 | 垂直切片，先打通核心链路再扩展 |
| mock 与真实数据差异 | 联调返工 | 早期定义 DTO 与表结构，接口契约先行 |
| 师傅端/PC 端尚未启动 | 交付不完整 | Phase 3 集中资源建工程 |
| 容量/SLA 规则需运营确认 | 业务正确性 | 规则引擎参数化，Apollo 可热更，先默认值后调优 |
| 多端主题与权限一致性 | 体验/安全 | 统一设计 token 与 RBAC 模型，前后端共约束 |

---

## 6. 验收标准（建议）

- **功能**：13 个接口 100% 可用；小程序核心 7 页可操作；PC 后台关键模块可管理。
- **质量**：核心算法有 Demo/单测覆盖；关键路径有联调用例。
- **安全**：RBAC 生效，越权接口返回 401/403。
- **运维**：提供建表 SQL、部署脚本、配置模板、故障排查手册（见《运维操作说明书》）。
- **可观测**：关键业务指标有看板。
