## 3. 数据库初始化

后端启动参数带 `createDatabaseIfNotExist=true`，首次启动自动建库。表结构与种子数据由以下脚本执行（启动自动跑，幂等）：

- `backend/src/main/resources/db/schema.sql` —— 28 张表结构（含 `CREATE TABLE IF NOT EXISTS` 与历史列补齐 ALTER 守卫）。
- `backend/src/main/resources/db/data.sql` —— 全量种子（`INSERT IGNORE`，重复启动不覆盖运行期数据）。

手动初始化（如需独立执行）：

```bash
mysql -u<user> -p < broadband < backend/src/main/resources/db/schema.sql
mysql -u<user> -p < broadband < backend/src/main/resources/db/data.sql
```

## 4. 后端构建与启动

### 4.1 构建（离线）

```bash
cd backend
/Users/mezo/Documents/localRepository/devRepository/maven/bin/mvn -o -q package -DskipTests
# 产出 target/broadband-backend-1.0.0.jar
```

### 4.2 启动（生产姿态，单 JVM）

> ⚠️ **禁止** `mvn spring-boot:run` 用于生产验证：本沙箱中该方式会被注入随机端口（fork JVM）。
> 必须用 `java -jar` 显式指定端口，程序参数优先级最高。

```bash
export DB_HOST=127.0.0.1
export DB_PORT=3306
export DB_NAME=broadband
export DB_USERNAME=broadband
export DB_PASSWORD=broadband

java -jar target/broadband-backend-1.0.0.jar --server.port=8082
```

### 4.3 多环境 Profile

`application.yml` 仅放公共配置；环境差异在 `application-dev.yml` / `application-prod.yml`：

```bash
# 生产
java -jar broadband-backend-1.0.0.jar --spring.profiles.active=prod --server.port=8082
```

环境变量注入优先级：`命令行参数 > 环境变量 > application-prod.yml > application.yml`。

## 5. 前端（web-admin）构建与托管

```bash
cd web-admin
npm install --registry=https://registry.npmmirror.com
npm run build            # 产出 dist/
```

Nginx 反代示例：

```nginx
server {
    listen 80;
    root /var/www/web-admin/dist;
    location / { try_files $uri $uri/ /index.html; }
    location /api/ {
        proxy_pass http://127.0.0.1:8082/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> 开发态：`VITE_API_TARGET` 指向后端地址，Vite 代理 `/api` 到 8082。

## 6. 容器化部署

`backend/Dockerfile` 为**多阶段**构建（Maven 构建层 + Temurin 21 JRE 运行层）：

```bash
docker build -t broadband-backend:1.0.1 backend/
docker run -d -p 8082:8082 \
  -e DB_HOST=$DB_HOST -e DB_USERNAME=broadband -e DB_PASSWORD=broadband \
  broadband-backend:1.0.1
```

## 7. 监控与可观测性

### 7.1 应用指标（Actuator + Prometheus）

已引入 `spring-boot-starter-actuator` 与 `micrometer-registry-prometheus`，开放端点：

| 端点 | 用途 |
|------|------|
| `/actuator/health` | 健康检查（K8s/Docker 探针） |

- 平均时延 > 1s 告警
- 5xx 错误率 > 5% 告警

阈值与 PC 后台「性能监控」页一致。

`scripts/k6-load-test.js`：覆盖 登录→订单→销售→工单→派单，20→50 VU 基线，P95 < 800ms、失败率 < 1%。

## 9. 运维操作手册

### 9.1 健康检查

```bash
curl -s http://127.0.0.1:8082/actuator/health   # {"status":"UP"}
```

### 9.2 重启（安全顺序）

```bash
pkill -f "broadband-backend-1.0.0.jar"   # 先停
sleep 2
java -jar target/broadband-backend-1.0.0.jar --server.port=8082 &
```

> ⚠️ 长驻服务请用进程守护（systemd / supervisor / k8s），避免 shell 退出被回收。

### 9.3 回滚

保留最近 3 个 jar 版本，回滚即替换 jar 并重启；数据库 schema 向后兼容（仅追加列，不删改）。

### 9.4 常见故障

| 现象 | 原因 | 处置 |
|------|------|------|
| 启动后立即退出 | 数据库连接失败 / 账号密码错 | 核对 `DB_USERNAME/DB_PASSWORD`，确认 `broadband` 库存在 |
| 全部接口 401 | JWT 被 `JwtAuthFilter` 静默拒绝 | 检查 token 是否过期、角色/部门是否匹配 |
| 全部接口 401（`iat/exp` 解析异常） | JWT 声明数字解析缺陷（已修复） | 升级到含修复的版本 |
| 派单容量异常 | 小区相邻性未识别 | 核查 `community.street` / 经纬度 |
| 报表数据为空 | 数据权限行级隔离过滤 | 用 admin（无部门）核对 `dept_id` 归属 |

## 10. 安全基线

- 认证：自研 HS256 JWT，零三方依赖；令牌含 `dept`（CUSTOMER / WORKER / ADMIN 类）。
- 授权：每请求实时查库（`@PreAuthorize` + 权限码），21 个权限码 / 5 角色 / 26 菜单三处同源。
- 数据权限：运营按 `dept_id` 含下级过滤，admin（`dept_id` 空）看全量。
- 审计：`sys_oper_log` 记录关键操作。
- 传输：反向代理层启用 HTTPS（生产强制）。

## 11. 备份与容灾

| 对象 | 频率 | 方式 |
|------|------|------|
| MySQL | 每日全量 + 增量 binlog | `mysqldump` / 云 RDS 自动备份 |

RTO < 30min，RPO < 5min（binlog）。
