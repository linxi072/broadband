# T-03 微信支付真集成 · 集成方案与凭证清单

> 迭代：T-03（微信支付真集成） · 日期：2026-09-20 · 状态：🔶 脚手架已就绪（**阻塞于商户凭证**，凭证到位即插即用）

## 1. 现状
- `PayService` 仅为接口，原 `MockWeChatPayServiceImpl` 已移除（伪造支付成功会推进未收款订单履约，属资金/履约双重隐患）。
- `OrderService` 通过 `@Autowired(required=false) PayService` 注入：无实现时直接拒绝支付（fail-closed），绝不伪造成功。
- 此前唯一缺口：**缺少真实 APIv3 实现 + 异步回调入口**。本次补齐。

## 2. 本次交付（脚手架，已编译通过、启动无侵入）
| 文件 | 作用 |
|---|---|
| `product/pay/WechatPayProperties.java` | 配置项载体（敏感信息走 yml/环境变量，不落 sys_config） |
| `product/pay/WechatPayV3Client.java` | APIv3 客户端（纯 JDK：RSA 签名、AES-256-GCM 解密、平台证书验签，无第三方 SDK 依赖） |
| `product/pay/WechatPayConfig.java` | 装配：`wechat.pay.enabled=true` 才创建支付 Bean（默认 false，保持安全默认） |
| `product/pay/WechatPayServiceImpl.java` | `PayService` 实现：JSAPI 统一下单 → 组装 `wx.requestPayment` 参数；退款调 APIv3 |
| `product/pay/WechatPayNotifyController.java` | `/api/pay/wechat/notify` 公网回调：验签 + 解密 + 置 PAID（已加入 SecurityConfig 免鉴权） |
| `OrderService` 改动 | 新增 `confirmPaid()`（回调最终置 PAID + 生成安装工单）；`pay()` 改为返回 prepay 参数（awaitPayment，不再同步置 PAID）；`refund()` 接入真实退款 |
| `PayService` 接口 | 新增 `pay(...,openid)` 与 `refund(...)` 默认方法，向后兼容 |

## 3. 调用时序
```
小程序                        后端                         微信支付
  │  POST /api/order/pay ──►  OrderService.pay()
  │                            └─ WechatPayServiceImpl.pay()
  │                                 └─ 统一下单 /v3/pay/transactions/jsapi
  │                                      ◄── prepay_id
  │                            ◄── { awaitPayment, payParams(wx.requestPayment 参数) }
  │  wx.requestPayment(payParams)
  │  ─────────────────────────────────────────────►  用户支付
  │                                       微信异步通知 POST /api/pay/wechat/notify
  │                            WechatPayNotifyController
  │                              ├─ 平台证书验签 + APIv3 解密
  │                              └─ OrderService.confirmPaid() → 置 PAID + 生成安装工单
```

## 4. 配置项（application.yml / 环境变量，禁用时无需填写）
```yaml
wechat:
  pay:
    enabled: false          # 凭证到位改 true
    mch-id:                 # 商户号
    app-id:                 # 小程序 AppID（师傅端/客户端各自不同）
    api-v3-key:             # APIv3 密钥（32 字节，回调解密用）
    serial-no:              # 商户 API 证书序列号
    private-key: |          # 商户 API 私钥（PEM，PKCS#8）
      -----BEGIN PRIVATE KEY-----
      ...
      -----END PRIVATE KEY-----
    notify-url:             # 公网可访问的回调地址，如 https://api.example.com/api/pay/wechat/notify
```

## 5. 凭证清单（向业务方/微信商户平台获取）
| 凭证 | 获取位置 | 用途 |
|---|---|---|
| 微信商户号 mchid | 微信支付商户平台 | 发起交易主体 |
| 小程序 AppID | 微信公众平台 | JSAPI 下单 `appid` |
| APIv3 密钥 | 商户平台 → APIv3 密钥设置 | 回调解密 / 证书解密 |
| 商户证书（私钥 + 序列号） | 商户平台 → API 证书 | 请求签名（`Authorization` 头） |
| 平台证书（自动拉取） | `/v3/certificates` 接口 | 校验微信回调签名 |
| 支付结果通知地址 | 自行部署的公网 HTTPS | 接收异步回调 |

## 6. 凭证到位后联调步骤
1. 填齐 `wechat.pay.*` 并设 `enabled=true`；
2. 将 `notify-url` 指向可公网访问的后端（需 HTTPS + 域名备案）；
3. 小程序 `pay` 入参补充 `openid`（登录态换取），后端透传 JSAPI payer；
4. 走「小额支付 → 回调 → 订单 PAID → 生成工单 → 退款」全链路；
5. 用 `R4 refund_no` 对接真实退款单号（已在 `OrderService.refund` 接入 `payService.refund`）。

## 7. 待确认 / 已知开放项
- **金额单位**：`OrderService` 当前 `amount` 按「元」存储，已按 `×100` 转「分」调用微信；**需联调确认订单 `amount` 列实际单位**，避免翻倍/缩水。
- **openid 来源**：JSAPI 必须 `payer.openid`，当前由小程序 `pay` 入参传入；建议改为由 `customer` 表持久化 openid，避免前端篡改。
- **部分退款 / 对账**：当前 `refund()` 为全额退款；部分退款、对账单（`/v3/bill`）、退款回调需后续补全。
- **证书自动续期**：`WechatPayV3Client` 已支持 `/v3/certificates` 拉取与缓存，但平台证书到期轮换建议加定时刷新。
