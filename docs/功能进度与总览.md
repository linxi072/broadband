## 一、项目总览

宽带业务管理系统是一套面向「家庭宽带办理与装维运营」的业务平台，覆盖 **客户端（微信小程序）**、**PC 后台管理系统（web-admin，Vue 3，已落地）** 与 **后端服务（Spring Boot 单体）** 三端。系统以「下单 → 小区可装性校验 → 智能派单 → 装维 SLA/赔付 → 套餐升级与流量监控」为主线，参考中国电信「美好家 / FTTR / 慢必赔」与中国移动「和家庭 / 承诺消费送宽带 / 流量提醒」等真实业务实践细化功能。

### 1.1 架构决策（已锁定）

- **单体架构**：后端为单一 Spring Boot 应用，**不引入 Spring Cloud / 微服务 / 服务注册发现 / 分布式网关**。
- **前端形态**：PC 后台为 Vue 3 单页应用，经 Nginx 反向代理直连后端 `:8082`。
- **模块上限**：后端业务模块上限 5 个，当前 4 个（community / install / product / system）。
- **配置策略**：优先使用 Spring Boot 原生（`application.yml` + 环境变量），外部配置中心（含 Apollo）暂不引入。

## 二、产品定位

- **业务主线**：下单 → 小区可装性校验 → 智能派单 → 装维 SLA/赔付 → 套餐升级与流量监控。
- **目标用户三角色**：① 终端客户（微信小程序自助办理）；② 安装师傅（独立小程序履约）；③ 运营/客服/财务（PC 后台管理）。
- **参考实践**：中国电信「美好家 / FTTR / 慢必赔」、中国移动「和家庭 / 承诺消费送宽带 / 流量提醒」。
- **关键业务能力**：融合套餐算价与补差升级、宽带可装性实时校验与需求登记、基于容量策略的智能派单、装维 SLA 双维度（时限类 + 速率类）评估与赔付、流量监控与续费提速、师傅端工单履约与数据隔离。
- **端到端链路**：`web-admin(Vue3) → Vite/Nginx → Spring Boot(:8082) → MySQL`（已 curl 实测）；小程序端经 `微信开发者工具 → 后端 :8082`（C 端登录态已接入真实 JWT 鉴权）。

### 6.5 历史真实缺陷（可追溯）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 登录成功、token 正确但所有受保护接口一律 401 | `JwtUtil` 数字判定误写导致 `iat`/`exp` 解析失败，过滤器静默吞异常 | 改为 `Character.isDigit`；过滤器补 WARN 日志；新增 7 条单测 |
| 2 | `GET /api/admin/orders` 返回 500 | 联表 `SELECT id` 未加表别名 → 列歧义 | 全部列加 `o.` 前缀 |
| 3 | `SlaEvaluation.summary` 输出 `[null]` | 主键在评估之后才生成 | 主键改为评估前生成 |
| 4 | 客户端「套餐列表」无数据 | `api.listPackages()` 请求 `/api/package/list` 无此端点 → 404 | 后端新增 `GET /api/package/list` 及 Mapper |
| 5 | 客户端「我的订单」空/被拦截 | `api.getOrders()` 请求 `/api/admin/orders`（越权 → 403） | 后端新增 `GET /api/order/my`；客户端改调 |
| 6 | 小程序登录形同虚设 | `login()` 本地返回假 token，未与后端交互 | 后端新增 `POST /api/auth/miniapp-login` 签发真实 JWT |
| 7 | 任何接口报错都被当成成功 | `request()` 仅 `fail` 时 reject，`statusCode>=400` 仍 resolve | 改为非 2xx 一律 reject（带 message） |
| 8 | C 端令牌「能签发却用不了」恒 401 | `JwtAuthFilter` 只认 `sys_user` 表，CUSTOMER 令牌不在后台用户表 | 过滤器按 `dept` 分支建 `CustomerPrincipal`/`WorkerPrincipal` |
| 9 | 师傅端登录形同虚设 | `workerLogin()` 本地返回假 token | 后端新增 `POST /api/auth/worker-login` 签发 WORKER 令牌 |
| 10 | 师傅端能看到全部工单 | 复用后台端点无 worker 过滤，且客户端可传 `?workerId=` | 新增 `/api/worker/*` 服务端按 token 强制过滤 |
| 11 | 师傅端 4 页硬编码假数据 | 首页统计/容量/排班/完工均写死，提交只是 `setTimeout` | 新增 worker 真实接口，4 页改调，`work_order` 增 5 列落库 |
